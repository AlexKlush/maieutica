# Майевтика

Сократический тьютор: после короткого текста (сейчас — про OKR) ведёт структурированный диалог, где ученик рассуждает сам.
Конвейер: диагностика реплики → модель ученика (BKT) → педагогическая политика → генерация → проверка. LLM — GigaChat.
Подробности — в [PRODUCT.md](PRODUCT.md) и [research/REPORT.md](research/REPORT.md).

## Запуск

Нужен Python 3.9 или новее (подойдёт и системный `python3` на macOS). В папке проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Откроется `http://localhost:8501`. В следующий раз достаточно `source .venv/bin/activate` и `streamlit run app.py`.
Без ключа приложение тоже запускается — в **автономном режиме** (см. ниже). Проверка, что сервер жив: `http://localhost:8501/_stcore/health` отвечает `ok`.

## Подключение GigaChat

Нужен **Authorization key** — ключ авторизации из личного кабинета: [developers.sber.ru](https://developers.sber.ru) → проект GigaChat API → «Настройки API» → «Получить ключ». Это длинная строка base64; Client ID или Client Secret по отдельности не подойдут.

Быстрее всего — вставить ключ в боковой панели приложения («Ключ GigaChat» → «Подключить»): он проверится сразу и будет жить только в памяти этой вкладки. Чтобы не вводить его каждый раз, положите в папку проекта файл `.env` (он в `.gitignore`):

```bash
GIGACHAT_CREDENTIALS=ваш_Authorization_key
```

Все источники ключа, по порядку: переменная окружения `GIGACHAT_CREDENTIALS` → Streamlit Secrets (`.streamlit/secrets.toml` или Settings → Secrets на Streamlit Cloud) → файл `.env`. Вместо готового ключа можно задать пару `GIGACHAT_CLIENT_ID` и `GIGACHAT_CLIENT_SECRET`. Ключ, поменянный в `.env`, подхватывается без перезапуска.

- **Scope** (тип ключа) подбирается сам: `GIGACHAT_API_PERS` — физлицо, `GIGACHAT_API_B2B` — предоплата юрлица/ИП, `GIGACHAT_API_CORP` — постоплата. Задать явно — `GIGACHAT_SCOPE`.
- **Модели.** По умолчанию все роли (диагностика, реплика, проверка) — `GigaChat-2-Max`. Сменить: меню «Модель GigaChat» в боковой панели, переменная `GIGACHAT_MODEL` для всех ролей или секция `[models]` в Secrets для каждой. Если у модели закончились токены (ответ 402) или её нет в API (404), приложение само отвечает следующей: `GigaChat-2-Max` → `GigaChat-2-Pro` → `GigaChat-2`, и пишет об этом в боковой панели и в трассе хода. Оценка качества (`eval/`) модели не подменяет.
- **Сеть.** Нужен исходящий доступ к `ngw.devices.sberbank.ru:9443` (OAuth) и `gigachat.devices.sberbank.ru:443` (API); если второй недоступен, клиент пробует новый адрес `api.giga.chat`. Сертификаты Минцифры лежат в `certs/`, общедоступные корни берутся из `certifi`, поэтому отдельно ставить сертификаты не нужно. Адреса можно переопределить: `GIGACHAT_AUTH_URL`, `GIGACHAT_API_URL`.

Что именно не так, скажет `python -m maieutica.doctor` (см. ниже) или ошибка под полем ключа.

## Автономный режим

Если ключа нет, сеть закрыта или GigaChat не отвечает, тьютор не падает, а отвечает **по правилам, без нейросети**: реплику ученика разбирают ключевые слова и карта знаний урока, ответ собирается из банка вопросов, подсказок и контрпримеров урока. Политика, модель ученика и проверка по правилам работают как обычно, но реплики проще и однообразнее.

- В интерфейсе это видно: красный блок «Автономный режим» или «GigaChat недоступен» с причиной в боковой панели и пометка «автономно» у каждого такого хода. Пока ключ найден, но GigaChat ещё не отвечал, блок нейтральный: «Ключ GigaChat найден».
- После сбоя соединения GigaChat помечается недоступным на 45 с (при повторных сбоях — дольше, до 10 минут), чтобы приложение не ждало таймаутов. Кнопка «Проверить подключение» возвращает GigaChat в работу.
- Оценка качества (`eval/`) автономный режим **не использует**: любой сбой LLM там виден, а не подменяется правилами.

## Диагностика

```bash
python -m maieutica.doctor            # ключ (где найден, похож ли на Authorization key), сеть, OAuth и scope, модели, запрос по каждой роли
python -m maieutica.doctor --json     # то же машиночитаемо
```

Код возврата: `0` — GigaChat отвечает, `2` — работает только автономный режим, `1` — что-то сломано.

Тесты (`pytest`) идут без сети. Весь путь запросов можно прогнать и без настоящего ключа — на заглушке API, которая умеет изображать ключ другого типа, закончившиеся токены и пропавшую модель:

```bash
python -m tests.fake_gigachat 8765 --exhausted GigaChat-2-Max &
GIGACHAT_CREDENTIALS=ZmFrZTpmYWtl GIGACHAT_AUTH_URL=http://127.0.0.1:8765/api/v2/oauth \
GIGACHAT_API_URL=http://127.0.0.1:8765/api/v1 streamlit run app.py
```

## Структура

`app.py`, `app.css` — интерфейс · `maieutica/` — конвейер (`analyzer`, `policy`, `learner`, `generator`, `verifier`, `engine`, `offline`, `llm`, `doctor`) · `lessons/` — уроки как данные · `eval/` — оценка на симулированных учениках · `research/` — обзор литературы · `tests/`.
