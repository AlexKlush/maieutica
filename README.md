# Росток

Сократический тьютор по любому материалу. Вставьте конспект, статью или главу — или просто назовите тему, и Росток напишет короткий конспект сам (нужен GigaChat). Дальше он не читает лекцию, а задаёт вопросы: ученик рассуждает сам, застрял — получает подсказки по нарастающей, ошибся — контрпример, а не «неправильно».
Конвейер: диагностика реплики → модель ученика (BKT) → педагогическая политика → генерация → проверка. LLM — GigaChat.
Метод — майевтика, «повивальное искусство» Сократа; подробности — в [PRODUCT.md](PRODUCT.md) и [research/REPORT.md](research/REPORT.md).

## Запуск

Нужен Python 3.9 или новее (подойдёт и системный `python3` на macOS). В папке проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Откроется `http://localhost:8501`. В следующий раз достаточно `source .venv/bin/activate` и `streamlit run app.py`.
Без ключа приложение тоже запускается — в **автономном режиме** (см. ниже). Проверка, что сервер жив: `http://localhost:8501/_stcore/health` отвечает `ok`.

## Как пользоваться

- **Главная** — «Над чем сегодня поработаем?». В поле можно вставить текст (от пары абзацев, до 15 000 знаков — длиннее обрезается), перетащить файл `.txt`/`.md` или написать тему: короткий запрос вроде «фотосинтез» считается темой. Под полем видно, как Росток понял ввод («Материал · 1 940 знаков» или «Тема — подготовлю конспект»).
- **План разбора.** По тексту строится карта: 3–6 смысловых частей и итоговое «Применение», у каждой — ожидаемое понимание, вопросы и лестница подсказок. С GigaChat карту строит модель (с типичными заблуждениями и кейсами), без него — правила: части по заголовкам и абзацам, названия — ключевые словосочетания текста (морфология — `pymorphy3`). Этапы разговора: Вспоминаем → Исследуем → Применяем → Осмысляем → Итог.
- **Разборы** слева, как чаты: у каждого — свой материал и прогресс. Они живут в памяти сервера, пока приложение запущено, и привязаны к браузеру (переживают перезагрузку страницы). Там же — **примеры**: OKR (урок, размеченный вручную), фотосинтез, инфляция, память — тексты из `lessons/examples/`.
- **Материал и прогресс** — панель справа (кнопки в верхней строке или полоска у правого края): текст, план разбора и насколько понятна каждая часть.
- Меню **«+»** в разборе: ответить за «трудного ученика» (верный ответ, заблуждение, «просто скажи ответ», «не знаю», раздражение, офтоп, взлом роли), перейти к практике или итогу, начать заново, скачать лог. Под каждым вопросом тьютора — «Почему такой вопрос»: диагностика, выбранный ход и проверка.

## Подключение GigaChat

Нужен **Authorization key** — ключ авторизации из личного кабинета: [developers.sber.ru](https://developers.sber.ru) → проект GigaChat API → «Настройки API» → «Получить ключ». Это длинная строка base64; Client ID или Client Secret по отдельности не подойдут.

Быстрее всего — вставить ключ в настройках приложения (значок настроек внизу слева → «GigaChat» → «Подключить»): он проверится сразу и будет жить только в памяти этой вкладки. Чтобы не вводить его каждый раз, положите в папку проекта файл `.env` (он в `.gitignore`):

```bash
GIGACHAT_CREDENTIALS=ваш_Authorization_key
```

Все источники ключа, по порядку: переменная окружения `GIGACHAT_CREDENTIALS` → Streamlit Secrets (`.streamlit/secrets.toml` или Settings → Secrets на Streamlit Cloud) → файл `.env`. Вместо готового ключа можно задать пару `GIGACHAT_CLIENT_ID` и `GIGACHAT_CLIENT_SECRET`. Ключ, поменянный в `.env`, подхватывается без перезапуска.

- **Scope** (тип ключа) подбирается сам: `GIGACHAT_API_PERS` — физлицо, `GIGACHAT_API_B2B` — предоплата юрлица/ИП, `GIGACHAT_API_CORP` — постоплата. Задать явно — `GIGACHAT_SCOPE`.
- **Модели.** По умолчанию все роли (диагностика, реплика, проверка, карта урока) — `GigaChat-2-Max`. Сменить: переключатель модели в поле ввода или в настройках, переменная `GIGACHAT_MODEL` для всех ролей или секция `[models]` в Secrets для каждой. Если у модели закончились токены (ответ 402) или её нет в API (404), приложение само отвечает следующей: `GigaChat-2-Max` → `GigaChat-2-Pro` → `GigaChat-2`, и пишет об этом в настройках и в «Почему такой вопрос». Оценка качества (`eval/`) модели не подменяет.
- **Карта урока** — один долгий запрос (обычно 20–60 с): пока он идёт, в разборе видно, что происходит. Одинаковый текст второй раз не строится — карта берётся из кэша.
- **Сеть.** Нужен исходящий доступ к `ngw.devices.sberbank.ru:9443` (OAuth) и `gigachat.devices.sberbank.ru:443` (API); если второй недоступен, клиент пробует новый адрес `api.giga.chat`. Сертификаты Минцифры лежат в `certs/`, общедоступные корни берутся из `certifi`, поэтому отдельно ставить сертификаты не нужно. Адреса можно переопределить: `GIGACHAT_AUTH_URL`, `GIGACHAT_API_URL`.

Что именно не так, скажет `python -m maieutica.doctor` (см. ниже) или уведомление после «Подключить».

## Автономный режим

Если ключа нет, сеть закрыта или GigaChat не отвечает, тьютор не падает, а отвечает **по правилам, без нейросети**: карту урока строят правила, реплику ученика разбирают ключевые слова и карта знаний, ответ собирается из банка вопросов, подсказок и контрпримеров урока. Политика, модель ученика и проверка по правилам работают как обычно, но реплики проще и однообразнее. Конспект по теме без GigaChat не пишется — нужен готовый текст.

- В интерфейсе это видно: «Без нейросети» у переключателя модели и внизу слева, пометка «без нейросети» у каждого такого хода, причина — в настройках, в блоке «GigaChat».
- После сбоя соединения GigaChat помечается недоступным на 45 с (при повторных сбоях — дольше, до 10 минут), чтобы приложение не ждало таймаутов. «Проверить связь» возвращает GigaChat в работу.
- Оценка качества (`eval/`) автономный режим **не использует**: любой сбой LLM там виден, а не подменяется правилами.

## Диагностика

```bash
python -m maieutica.doctor            # ключ (где найден, похож ли на Authorization key), сеть, OAuth и scope, модели, запрос по каждой роли
python -m maieutica.doctor --json     # то же машиночитаемо
```

Код возврата: `0` — GigaChat отвечает, `2` — работает только автономный режим, `1` — что-то сломано.

Тесты (`pytest`) идут без сети. Весь путь запросов можно прогнать и без настоящего ключа — на заглушке API, которая строит карту урока, пишет конспект по теме и умеет изображать ключ другого типа, закончившиеся токены и пропавшую модель:

```bash
python -m tests.fake_gigachat 8765 --delay 1 &
GIGACHAT_CREDENTIALS=ZmFrZTpmYWtl GIGACHAT_AUTH_URL=http://127.0.0.1:8765/api/v2/oauth \
GIGACHAT_API_URL=http://127.0.0.1:8765/api/v1 streamlit run app.py
```

## Интерфейс

Весь интерфейс — собственный компонент Streamlit в папке `ui/` (обычные HTML, CSS и JS, без сборки): Streamlit только запускает Python и растягивает компонент на весь экран. Компоновка знакомая по чат-ассистентам: разборы слева (сворачиваются до полоски значков), диалог в центре, материал и прогресс справа.

- `ui/style.css` — токены светлой и тёмной темы (тёплая «бумажная» основа, один лаймовый акцент: кнопки, логотип, маркер под текущим вопросом), типографика, все анимации. Скругления маленькие и разные по роли, контраст текста проверен по WCAG AA в обеих темах.
- `ui/app.js` — главная, лента диалога, побуквенное появление ответа, «думаю» со стадиями конвейера, боковая и правая панели, меню, настройки, тема, уведомления. Прокручивается только лента: пока тьютор печатает, она следует за текстом, а если прокрутить вверх — остаётся на месте (кнопка «↓» возвращает вниз).
- `ui/index.html` — каркас и иконки; логотип-росток — свой; `ui/fonts/` — Literata (засечки) и Onest с кириллицей, лицензии в `ui/LICENSES.md`.
- `app.py` держит разборы (`Chats`), собирает состояние для интерфейса (`build_state`) и обрабатывает события из него (`handle`: новый разбор, пример, сообщение, переход к этапу, модель, ключ, удаление). Пока идёт работа, текущая стадия пишется в скрытый элемент `.mx-live`, откуда её читает индикатор.

Тема по умолчанию следует системе; переключатель — внизу слева и в настройках. При системной настройке «уменьшить движение» анимации отключаются.

## Структура

`app.py` — связка интерфейса с конвейером · `ui/` — интерфейс · `maieutica/` — конвейер (`materials` — урок из любого текста, `compiler` — карта урока от GigaChat, `analyzer`, `policy`, `learner`, `generator`, `verifier`, `engine`, `offline`, `llm`, `doctor`) · `lessons/` — уроки как данные и тексты примеров · `eval/` — оценка на симулированных учениках · `research/` — обзор литературы · `tests/`.
